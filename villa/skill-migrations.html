Castra Skill Migration Guide

Castra の共有 skill を、Revisor/Cc の現行 workflow に必要な最小面へ整理した内容を人間向けに説明する資料。active から外した内容は削除せず、Genius への判断移管または隔離として追跡する。

Villa は正本ではありません

このページは人間が移行状況を把握するための要約です。active / quarantine の正本は Castra、判断カードの正本は Genius、session workflow と local PR の正本は Cc / Revisor の実装・設定です。差異がある場合はそれぞれの正本を優先します。

GitHub は作業面ではない

  1. GitHub に PR は出さない。
  2. GitHub に feature / task branch を push しない。
  3. GitHub は release version 管理と release notes の公開以外に使わない。
  4. GitHub push と version 管理は Revisor が行う。

Villa ドキュメントは local main へ直接追加

Villa は各プロジェクトが人間向け資料を置く共有表示面である。各プロジェクトは専用の HTML ファイルと route を使い、Villa のローカル main へ直接 commit してよい。Villa のドキュメント追加では feature branch、worktree、local PR を必須にしない。他プロジェクトのページを上書きせず、Villa を情報の正本にはしない。

Castra も local main へ直接 commit

Castra は feature branch、worktree、Revisor local PR を作らず、Cc に実 checkout の main を登録してローカル main へ直接 commit する。共有 checkout に他セッションの差分がある場合は自分の対象 path だけを stage し、同じファイルで重なった場合は相手の差分を退避・上書きせず停止する。GitHub PR と branch push は行わず、release push と version 管理は Revisor に任せる。

Revisor + Cc 現行 workflow

01 / CLAIM

project を確定

project code と実 branch を確認し、Cc 経由で claim。指定 branch と違えば編集しない。

02 / IMPLEMENT

local main から隔離

通常 repo はローカル main から task worktree を作り、そこでだけ編集・commit する。Castra と Villa は direct-main 例外。

03 / REVIEW

local PR を提出

Cc から Revisor へ提出。結果は通知されるため、session は状態をポーリングしない。

04 / CONTINUE

通知駆動で完了

自動修正可能な失敗は直す。Test OK は Revisor auto-merge、必要時だけ人間判断。Goal & Go は600秒。
