# Ex Viewer と各サービスの統合動作を確認する

## 目的

統合 Viewer とサービス側のルーターベースパス対応を組み合わせたとき、単一 URL での利用と直接アクセスの双方が成立することを確認する。個別 PR の Test OK の通知だけで統合確認済みとはしない。

## 完了条件

- 掲載対象の確定と所有リポ側の設定・互換対応を前提に、Ex と対象フロントエンドの反映する版・手順・戻し方を記録する。
- 明示的なテスト実施許可と必要な反映許可を得て、プロジェクト本体フォルダのみを使用する。起動・再起動は Excubitor 経由とし、Concordia の testing claim を事前登録して終了時に release する。
- `/viewer/` からのサービス切替、配下ルートの直接表示・再読込・戻る/進む、API と静的アセットを確認する。対象が利用する認証、WebSocket/SSE、Worker、cookie/storage も必要に応じて確認する。
- サービス移動メニューは Ex Viewer 経由だけに現れ、サービスへ直接アクセスしたときの既存画面・ルーティングを壊さないことを確認する。
- 除外サービスが掲載されず、任意 URL/port への中継を許さないこと、CSP 等の保護が維持されることを確認する。
- 結果と不具合の再現手順を該当 TestWorkflow スレッドに記録する。不具合の修正は所有リポの別タスクに分ける。

## スコープ (編集可ディレクトリ)

- Excubitor の `spec/plan/`（確認手順・証跡）。
- 各プロジェクト本体は承認された反映・動作確認の範囲に限定する。実装ファイルの修正は含めない。

## 制約

このタスク定義の保存はテスト・マージ・main 更新の許可ではない。実施許可がなければ開始しない。worktree や複製フォルダから起動しない。進行状態は Concordia DB に保持する。
